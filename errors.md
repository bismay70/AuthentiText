# Technical Errors & Resolution Log

This document serves as an incident report detailing the specific technical errors, bugs, and logic flaws encountered during the development lifecycle, and the explicit resolutions implemented to fix them.

---

### Error 1: Model "Cheating" via Superficial Formatting (The 13% Accuracy Trap)
*   **Symptoms:** During initial validation phases, the model was stuck at a severe local minimum, oscillating around ~13% accuracy.
*   **Diagnosis:** The transformer was overfitting to presentation rather than style. It learned that specific models use certain markdown artifacts (e.g., ChatGPT's specific table formatting, Claude's use of bullet points) and ignored the underlying linguistic syntax.
*   **Resolution:** Developed `test_utils.py` containing `clean_stylometric_text()`. This function utilizes regular expressions to strip out hashes, asterisks, bullet markers, and layout artifacts before tokenization, forcing the model to read the syntax blindly.

### Error 2: Categorical Target Index Mismatch
*   **Symptoms:** PyTorch DataLoader threw shape and indexing errors during the loss calculation phase of the training loop.
*   **Diagnosis:** The raw datasets contained string labels for categories (e.g., 'chatgpt', 'claude'). The PyTorch `CrossEntropyLoss` function strictly expects zero-indexed numerical tensors (0 to N-1 classes).
*   **Resolution:** Implemented a hardcoded `label_map` dictionary in `local_tune.py` (`{'chatgpt': 0, 'claude': 1...}`). Added strict dataset mapping that drops any mismatched strings and casts the results safely to `torch.long` tensors before yielding batches.

### Error 3: Catastrophic Forgetting during Fine-Tuning
*   **Symptoms:** As training progressed over epochs, validation loss began to skyrocket, and the model lost basic contextual understanding, classifying completely unrelated texts randomly.
*   **Diagnosis:** The learning rate applied during fine-tuning was too high for an unfrozen pre-trained model. The aggressive gradient updates were destroying the foundational linguistic weights DistilBERT had learned during its initial pre-training.
*   **Resolution:** Unfroze the base encoder blocks but throttled the optimizer. Switched to `AdamW` with a highly conservative learning rate of $2\times 10^{-5}$, limiting training to just 5 epochs to prevent representational collapse.

### Error 4: Adversarial Spoofing (57% Accuracy Drop)
*   **Symptoms:** When testing the model with adversarial prompts (e.g., asking Gemini to "write in the tone of an overly formal AI"), the sequence classifier failed catastrophically, dropping from 93.28% to 36.00% accuracy.
*   **Diagnosis:** Pure sequence classifiers are blinded by style-mimicry because they evaluate sequential token probability, which the LLMs successfully spoofed.
*   **Resolution:** Built the Hybrid Ensemble Architecture. Blended the DistilBERT logits with a Gradient Boosting Model running on hard macro-statistics (punctuation frequency, average word length). While LLMs spoofed the sequence, they could not spoof the mathematical macro-features, stabilizing the final output.

### Error 5: Cloud Deployment Crashes (Large Weights Limit)
*   **Symptoms:** Pushing the repository to GitHub and deploying to Streamlit Community Cloud caused the deployment build to fail and crash immediately.
*   **Diagnosis:** The PyTorch `.safetensors` state dictionary generated by `local_tune.py` was too large for GitHub's file limits and Streamlit's memory constraints.
*   **Resolution:** Implemented Dynamic Environment Routing. Added OS-level path checks (`os.path.exists`) in `app.py`. If the heavy local weights are untracked (due to `.gitignore`), the script dynamically catches the failure and pulls the lightweight `distilbert-base-uncased` base model directly from the Hugging Face hub, allowing the UI to remain functional in a sandbox mode.
